# 05802.github.io

A Jekyll-based personal site with automated AI-generated intelligence briefings. The site publishes two types of content: manually written posts and automated "news roll" items generated by LLMs on a schedule.

## Site Structure

```
.
├── _posts/              # Manual blog posts (essays, notes)
├── _roll/               # Auto-generated news items (AI briefings)
├── prompts/             # LLM prompts for each task
├── config/              # Task configuration (tasks.yaml)
├── src/                 # Python generation engine
├── .github/workflows/   # GitHub Actions for scheduled generation
└── assets/library/      # PDF library files
```

## How It Works

The generation system follows a straightforward pattern:

1. **GitHub Actions** trigger on a schedule (cron)
2. **main.py** loads the task config and reads the prompt files
3. **OpenAI's API** (GPT-5.2 with web search) generates content based on the prompt
4. **Output** is saved to `_roll/` with Jekyll front matter
5. **Auto-commit** pushes the new file, Jekyll rebuilds, site updates

### The Generation Pipeline

```
Workflow trigger → main.py --task <name> → load prompt → call LLM → save to _roll/ → git commit
```

The `ContentGenerator` class handles the API call. For GPT-5.2, it uses OpenAI's Responses API with web search enabled, allowing the model to fetch current information. Streaming is enabled to prevent timeout issues on long-running requests.

## Key Files

| File | Purpose |
|------|---------|
| `main.py` | Entry point. Parses args, loads config, orchestrates generation |
| `config/tasks.yaml` | Defines all tasks: which prompt, model, provider, and settings |
| `prompts/*.txt` | The actual prompts. Each task has a dedicated prompt file |
| `prompts/system_prompt.txt` | Shared system instructions (critical thinking, output format) |
| `src/generator.py` | LLM API integration (OpenAI Responses API, Chat Completions fallback) |
| `src/client_factory.py` | Returns configured OpenAI/xAI clients based on provider |
| `src/models.py` | Pydantic models for task config validation |
| `src/utils.py` | File I/O and config loading helpers |
| `.github/workflows/*.yml` | Scheduled GitHub Actions for each task |

## Adding a New Automated Task

1. **Create the prompt** in `prompts/your_task.txt`
2. **Add the task** to `config/tasks.yaml`:
   ```yaml
   tasks:
     your_task:
       prompt_file: "prompts/your_task.txt"
       system_prompt_file: "prompts/system_prompt.txt"
       provider: "openai"
       model: "gpt-5.2"
       reasoning_effort: "high"
       verbosity: "medium"
       title: "Your Task Title"
   ```
3. **Create a workflow** in `.github/workflows/your_task.yml`:
   ```yaml
   name: Your Task Generation

   on:
     schedule:
       - cron: '20 2 * * 1'  # Pick a unique time slot
     workflow_dispatch:

   jobs:
     build:
       runs-on: ubuntu-latest
       timeout-minutes: 40
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-python@v4
           with:
             python-version: '3.10'
         - run: pip install -r requirements.txt
         - env:
             OPENAI_API_KEY_NEWSLETTERS: ${{ secrets.OPENAI_API_KEY_NEWSLETTERS }}
           run: python main.py --task your_task
         - uses: stefanzweifel/git-auto-commit-action@v4
           with:
             commit_message: "New Your Task content generated"
             file_pattern: "_roll/*.md"
   ```

**Scheduling note:** Stagger workflow start times by 10+ minutes to avoid API rate limits and resource contention.

## Manual Content

Posts in `_posts/` are written manually and follow standard Jekyll naming: `YYYY-MM-DD-title.md`. These appear on the main index page.

The `_roll/` collection is for automated news items. These appear on `/news` and have their own RSS feed at `/news-feed.xml`.

## Running Locally

```bash
# Install dependencies
pip install -r requirements.txt

# Dry run (see what would happen without calling the API)
python main.py --dry-run

# Run a specific task
OPENAI_API_KEY_NEWSLETTERS=sk-... python main.py --task frontier_labs

# Run all tasks
OPENAI_API_KEY_NEWSLETTERS=sk-... python main.py
```

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `OPENAI_API_KEY_NEWSLETTERS` | Yes | OpenAI API key for GPT-5.2 |
| `XAI_API_KEY_NEWSLETTERS` | No | xAI API key (if using xAI provider) |

## Output Format

Generated files land in `_roll/` with this structure:

```
_roll/2026-01-06-0335-frontier_labs.md
```

The filename format is `YYYY-MM-DD-HHMM-taskname.md`. Each file includes Jekyll front matter:

```yaml
---
layout: news
title: "Frontier Labs"
date: 2026-01-06
permalink: /news/202601060335_frontier_labs/
---
```

The permalink ensures unique URLs even if multiple items generate on the same day.
